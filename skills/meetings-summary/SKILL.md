# 고객사 미팅 요약 구조

고객사 미팅(Discovery call, Pre-meeting, 워크샵 등) 정보를 요약할 때 다음 순서로 정렬:

1. **기본 정보**: 날짜, 시간, 장소, 참석자, 인원
2. **고객사 요청/배경** (출처 명시):
   - 고객이 왜 연락했는가
   - 구체적 요청사항 (직접인용 우선)
   - 단장/의사결정자 발언 강조
3. **팀/고객사의 현재 상황**:
   - 구체적 문제점
   - 이전 시도 및 결과
4. **강연/워크샵 내용 또는 합의사항**
5. **정보 출처 명시**:
   - 각 주요 정보마다 `(출처: [미팅명] [날짜], [발화자])` 태그
   - Discovery vs Pre-meeting vs 기타 명확히 구분
6. **관련 원본 문서 링크**:
   - 미팅 기록, 사전설문, 계약서 등 접근 가능한 URL

# 예시

**고객사 요청 배경** (출처: Discovery call 4/27, 이건국 단장)
- "하네스 엔지니어링이 핵심 관심사" (직접발언)
- 팀 문제: 서브에이전트 활용 소수, evaluation 중심 진도 정체

**구체적 상황** (출처: Pre-meeting 5/12, 강민주)
- 웹 파트: 요구사항 분석→설계→기능 개발→QA 전 과정을 하네스 에이전트로 구축 완료
- AI 팀(2~3명): evaluation 중심의 agentic 방식 시도했으나 진도 정체
