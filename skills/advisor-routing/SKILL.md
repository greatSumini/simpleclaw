# Advisor 먼저 위임 원칙

## 언제 적용하는가

다음 패턴 중 하나라도 감지되면 즉시 구현 착수 전에 advisor 위임을 먼저 제안한다:

- **스키마·데이터 구조 설계**: "스키마 만들자", "구조 어떻게 잡을지", "어떤 필드가 필요한지"
- **아키텍처 의사결정**: "어떻게 설계할지", "어떻게 만들면 좋을지", "처음부터 좋은 구조로"
- **방향 불확실**: "뭐가 좋을까", "어떤 방식이 나을지", "방향을 잡고 싶어"

## 적용 순서 (반드시 이 순서를 지킨다)

1. **advisor 먼저 위임** — 구현 전에 advisor와 방향·스키마를 확정한다
2. **방향 확정 확인** — 사용자가 advisor 논의 결과를 공유하거나 방향이 명확해지면 진행
3. **구현 착수** — 확정된 방향 기반으로만 구현

## 위임 제안 예시

> "스키마/구조 설계가 포함된 요청이네요. advisor와 먼저 방향을 잡은 뒤 구현하면 수정 반복을 줄일 수 있습니다. advisor에게 위임할까요?"

## 예외: 즉시 구현해도 되는 경우

- 방향이 이미 명확히 확정된 후속 구현 요청 ("그 구조대로 만들어줘")
- 단순 타이핑 수정·이름 변경·문서 업데이트
- 사용자가 advisor 위임을 명시적으로 거부한 경우
